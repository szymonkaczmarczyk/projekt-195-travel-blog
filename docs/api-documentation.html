Dostęp i działanie

Projekt 195 nie ma serwera aplikacji. Wszystkie endpointy to pliki statyczne, które Astro zapisuje do dist/ podczas npm run build. Po wdrożeniu serwuje je zwykły hosting statyczny, tak samo jak obrazki i HTML. Dane zmieniają się tylko przy kolejnym buildzie.

Żaden endpoint nie wymaga uwierzytelniania, nagłówków ani kluczy. Strona nie ustawia ciasteczek i nie ma sesji.

CechaOpis
MetodyTylko GET (i HEAD, jeśli hosting go obsługuje). Nie ma endpointów zapisujących dane.
Nagłówki żądaniaNie są wymagane. Typ odpowiedzi wynika z rozszerzenia pliku i ustawień hostingu.
CORSZależy od hostingu. Domyślnie pliki są przeznaczone dla tej samej domeny, czyli dla skryptów strony.
CacheZależy od hostingu. Pliki w /_astro/ mają hash w nazwie i mogą być cache'owane na stałe; /data/*.json zmieniają się przy każdym buildzie.
LimityBrak limitów po stronie projektu. Ewentualne limity ustala hosting.

Przykład (curl):

curl https://<twoja-domena>/data/globe.json

curl -I http://localhost:4321/data/earth.json
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 50518

Endpointy /data/*.json są przeznaczone dla globusów na stronie. Można je czytać z zewnątrz, ale ich kształt jest podporządkowany rozmiarowi pliku (krótkie klucze), a nie wygodzie integracji.

Konwencje i błędy

ZasadaOpis
FormatJSON w UTF-8 dla /data/*.json, XML dla mapy strony, czysty tekst dla robots.txt.
Kod ISO3Trzyliterowy kod kraju (ISO 3166-1 alfa-3), np. ISL. Klucz w countries.json, photos.json i we frontmatterze.
Kod numerycznyPole id w JSON-ach to kod ISO 3166-1 numeryczny jako tekst z zerami wiodącymi ("004", "352"). Takich samych identyfikatorów używa world-atlas.
SlugPolska nazwa kraju małymi literami, bez znaków diakrytycznych, z myślnikami (bosnia-i-hercegowina). Adres strony kraju: /kraje/{slug}/.
Data wizytyWe frontmatterze YYYY-MM-DD. W JSON-ach jako polski miesiąc i rok ("czerwiec 2015"). Kraj domowy ma wartość "dom".
Współrzędnelat i lng w stopniach dziesiętnych, przybliżony środek kraju.
ObrazkiŚcieżki zaczynające się od /_astro/ to pliki wygenerowane przez astro:assets. Ich nazwy zawierają hash i zmieniają się przy zmianie pliku źródłowego.

Błędy nie mają formatu JSON: nieistniejący adres zwraca stronę 404.html z kodem HTTP 404.

curl -s -o /dev/null -w "%{http_code} %{content_type}\n" http://localhost:4321/data/nie-ma.json
404 text/html
KodKiedy
200Plik istnieje.
304Plik się nie zmienił od ostatniego pobrania (If-None-Match / If-Modified-Since), jeśli hosting to obsługuje.
404Nie ma takiego pliku ani strony. Treść to strona błędu w HTML.

GET/data/globe.json

GET https://<twoja-domena>/data/globe.json

Odpowiedź — błąd (404)

KluczOpis

GET /robots.txt

GET/robots.txt

Reguły dla robotów wyszukiwarek, generowane przez src/pages/robots.txt.ts. Wpuszcza wszystkie roboty i wskazuje pełny adres mapy strony zbudowany z SITE_URL.

Przykład żądania

GET https://<twoja-domena>/robots.txt

Odpowiedź — sukces

User-agent: *
Allow: /

Sitemap: https://projekt195.pl/sitemap.xml

Nic nie jest blokowane, także /data/ i /img/: wyszukiwarki potrzebują tych plików, żeby poprawnie wyrenderować strony z globusem.

Model treści: plik kraju

src/content/kraje/{slug}.md

Jeden plik to jeden odwiedzony kraj. Frontmatter jest walidowany schematem zod w src/content.config.ts; błąd w polu zatrzymuje build z komunikatem. Treść pod frontmatterem to relacja w markdownie.

Pola frontmattera

ParametrWymaganyOpis
countrytakKod ISO3 z countries.json, dokładnie 3 znaki. Nieznany kod zatrzymuje build.
visitedtakData pierwszej wizyty, YYYY-MM-DD. Decyduje o kolejności na listach.
daystakLiczba dni na miejscu, liczba całkowita ≥ 0.
ratingtakOcena od 1 do 5 (gwiazdki w tabeli faktów).
excerpttakZajawka: karta kraju, opis meta strony i karta na globusie. Najlepiej 80 do 155 znaków.
titlenieTytuł relacji i tytuł strony. Domyślnie „{nazwa}: relacja z podróży”.
routenieTrasa, punkty rozdzielone znakiem ·, np. Reykjavík · Ring Road · Fiordy Zachodnie.
topnietrue dodaje kraj do kolekcji „Najlepsze”. Domyślnie false.
homenietrue tylko dla kraju domowego: nie liczy się do „ostatnich pieczątek”, ma etykietę „punkt zero”.
tagsnieKolekcje tematyczne:
WartośćZnaczenie
wyspyWyspiarskie
goryGóry i wysoko
pustyniePustynie
dzika-przyrodaDzika przyroda
tropikiTropiki
photoSearchnie2 do 5 haseł dla npm run photos, najlepiej nazwy miejsc po angielsku albo lokalnie.

Skrypty generujące

Skrypty w scripts/ uruchamia się ręcznie (Node 22+, sharp). Ich wyniki są w repozytorium, więc zwykły build ich nie potrzebuje.

npm run photos (scripts/fetch-photos.mjs)

Dla każdego kraju bez kompletu zdjęć (co najmniej 3 albo tyle, ile haseł w photoSearch) szuka plików w Wikimedia Commons: najpierw wśród wyróżnionych, potem jakościowych, na końcu w całym zbiorze. Zapisuje WebP do src/assets/photos/ i metadane do photos.json.

ParametrWymaganyOpis
--only=ISL,NORnieTylko wskazane kraje (kody ISO3), także gdy mają już zdjęcia.
--forceniePobiera od nowa dla wszystkich krajów.
--metanieNie pobiera plików, tylko odświeża autorów i licencje (npm run photos:meta).
npm run photos -- --only=ISL

Nietrafione zdjęcia wyklucza się w scripts/photo-overrides.json (exclude: tytuły plików), a konkretne pliki można wymusić w files.ISO3. Skrypt przedstawia się ogólnym User-Agentem zgodnie z zasadami API Wikimedia i nie wysyła żadnych danych osobowych.

npm run countries (scripts/build-countries.mjs)

Generuje src/data/countries.json z bazy world-countries: 193 państwa ONZ, Watykan i Palestyna, polskie nazwy z poprawkami, slugi i kontynenty. Bez parametrów.

npm run earth / npm run globes (scripts/build-earth.mjs)

Z scripts/earth-source.jpg (NASA Blue Marble) i granic world-atlas 50m tworzy tekstury Ziemi, mapy identyfikatorów krajów i statyczne rendery globusa dla stron krajów.

ParametrWymaganyOpis
--globes-onlynieTylko rendery public/img/globes/{iso3}.webp (npm run globes).
--maps-onlynieTylko tekstury day-*.webp, ids-*.png i ids.json.
--only=ISLnieRendery globusów tylko dla wskazanych krajów.

npm run hero (scripts/hero-cutout.mjs)

Wycina pierwszy plan ze zdjęcia hero (wykrywanie linii nieba kolumna po kolumnie), dorysowuje niebo i zapisuje warstwy tła i pierwszego planu w trzech szerokościach oraz rozmyty podgląd.

ParametrWymaganyOpis
--inputniePlik źródłowy, domyślnie scripts/hero-source.jpg.
--outnieKatalog wyjściowy, domyślnie public/img/hero.
--widthnieSzerokość robocza, domyślnie 2560.
--thresholdnieCzułość wykrywania nieba, domyślnie 28.
--extendnieIle pikseli nieba dorysować nad zdjęciem, domyślnie 400.
--floornieRęczne poprawki linii nieba x0:x1:y rozdzielone przecinkami: w pasie od x0 do x1 (ułamki szerokości) niebo sięga co najmniej do wysokości y (ułamek wysokości). Skrypt npm używa 0:0.047:0.665.
--sizesnieSzerokości wyjściowe, domyślnie 960,1600,2200.

Po zmianie zdjęcia hero trzeba zaktualizować proporcje w Hero.astro (aspect-ratio, --stage-w) i pozycję tytułu, a potem zrobić nowy public/og/default.jpg.
